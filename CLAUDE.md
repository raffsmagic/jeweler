Jewel builds tiny on-device models that spot passwords, keys and codes (for apps that handle copied text). Start at README.md; the corpus plan is docs/corpus.md, results docs/benchmark.md, research docs/research.md.

- Never write real secrets or the owner's clipboard text to disk, the repo, logs or chat; report masked shapes (a/A/9) and counts.
- Paths containing "secret" or "credential" are blocked by the user's permission rules. The library is **jeweler**; its model is versioned on its own as v1, v2... (`models/jeweler-v1.json`; research notes say "Jewel 1/2/3", and v1 = Jewel 3; Jewel 1 and 2 were trained on private text and are not in this repo); "lock" is the app's verb for what it does with a hit, not Jewel's. Jewel returns a 0-1 score (null when its gate skips the text); the app picks the threshold.
- Every model change: retrain, run all three tests, export, run runtime/parity.ts, then update docs/benchmark.md.
- Policy, owner's call (2026-10-06): a new Jewel may never be worse than the shipped one on anything measured (recall floors sit inside the research metric, false-alarm caps are hard), and Jewel is tuned only for what the baseline rules miss (the exam removes what the rules lock). Anything with a prefix or a checksum belongs in the rules.
- Autoresearch lives in `research/`: an agent edits only `research/train.py`; `research/prepare.py` (the exam and the metric `fp94`) is frozen; every run is a row in `research/results.tsv`. The rules are `research/program.md`; experiments commit only that file (path-limited), never `git add -A` or `git reset --hard` while a loop runs.
